Three views, three meanings

Module imports

Module → imported module. The complete direct local import graph, parsed from every source header and checked against compiled headers. An import is not a theorem dependency.

Compiled declaration references

Declaration → referenced constant. Separate edges for the compiled type, theorem proof / definition value, and recursor rule RHS. Ownership comes from actual ModuleData.constNames, not namespaces.

Hand-selected Blueprint

Prerequisite → consumer (opposite direction). An explanatory selection, not the full import or Const graph. Read the mathematical narrative or inspect its projection below.

Coverage, external boundary, and cycles

All declarations in the local compiled constant census are included, including generated auxiliaries. A name can occur in several actual module censuses (for example, a regenerated equation lemma); all providers are retained, and reference signatures must agree before graph nodes are merged. Exported axiom-shaped signatures are completed with body-bearing private object parts. External or unresolved constants outside that census are retained by exact name, but are not assigned a package from their spelling or expanded. Local extraConstNames have their own boundary category when no body is available.

This is a static Expr.const graph, not arbitrary reflection, runtime calls, tactic execution, projection metadata, or dynamic lookup. Edges are unique references, not occurrence counts. Recursive clusters and self-edges are kept; we do not assume this graph is a DAG. Verified API anchors are used only when supplied by a real API bundle; other declarations link to their owning module at the recorded source commit.
